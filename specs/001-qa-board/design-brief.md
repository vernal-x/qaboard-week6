# QANOW 디자인 지시서 (Design Brief for Claude Design)

**Feature**: 001-qa-board
**근거 문서**: `.specify/memory/constitution.md`, `specs/001-qa-board/spec.md` (Clarifications 포함)
**작성일**: 2026-09-25
**용도**: Claude Design에 전달할 화면 설계 지시서. 이 문서는 정보 구조와 디자인 방향만 정의하며,
React/CSS 코드는 포함하지 않는다. spec.md에 없는 기능은 어떤 형태로도 추가하지 않는다.

## 1. 프로젝트와 사용자 요약

QANOW는 회원이 질문을 등록하고 관리자가 답변하는 질의응답 게시판이다. 사용자는 세 역할로
나뉜다: 비회원(서비스 소개만 열람), 회원(질문 등록·조회, 답변 전 수정·삭제, 답변 확인), 관리자
(전체 질문 조회, 답변 작성·수정). 회원은 다른 회원의 질문을 볼 수 없고, 관리자가 답변한 이후
회원은 해당 질문을 수정·삭제할 수 없다. MVP는 파일 첨부, 댓글, 검색, 페이지네이션, 소셜 로그인,
통계 대시보드를 포함하지 않는다.

## 2. 디자인 목표

- 현대적이고 모던한 인상을 주되, 흔한 AI 랜딩 페이지처럼 보이지 않을 것.
- "질문을 남기면 관리자가 확실히 답한다"는 신뢰감을 전달할 것.
- 메인 페이지는 강한 첫인상을 주는 진입점, 질문 리스트/질문 페이지는 가독성과 작업 효율을
  우선하는 작업 화면으로 톤을 분리할 것.
- 세 핵심 화면이 하나의 디자인 언어를 공유하도록(헌법 원칙 V) 설계하되, Hero 영역만 예외적으로
  강한 비주얼을 허용할 것.

## 3. 브랜드 키워드

신뢰(Trust) · 명료함(Clarity) · 응답성(Responsiveness) · 절제된 임팩트(Restrained Impact) ·
전문성(Professionalism). 화려함보다 "질문이 확실히 전달되고 답이 돌아온다"는 확신을 우선한다.

## 4. 핵심 화면 3개의 목적

1. **메인 페이지**: 방문자가 QANOW의 목적과 이용 흐름(질문 작성 → 관리자 확인 → 답변 확인)을
   별도 설명 없이 이해하고, 질문 작성으로 진입하게 한다.
2. **질문 리스트 페이지**: 회원은 자신의 질문과 답변 상태를, 관리자는 전체 질문과 답변 대기
   상태를 한눈에 파악하고 다음 행동(질문 작성 또는 답변 처리)으로 이어지게 한다.
3. **질문 페이지**: 질문 작성 · 상세 확인 · 수정 · 관리자 답변 작성/수정을 하나의 일관된
   레이아웃(제목·내용·답변 영역) 안에서, 모드에 따라 입력 가능 여부만 달리해 수행하는 화면이다.

## 5. 화면별 정보 우선순위

- **메인 페이지**: ① 서비스 한 줄 소개 → ② 이용 흐름 3단계 → ③ 질문 작성 CTA
- **질문 리스트 페이지**: ① 답변 상태(대기/완료) → ② 질문 제목 → ③ (관리자 뷰) 작성자 닉네임
  → ④ 등록일시 → ⑤ 상태 필터
- **질문 페이지**: ① 답변 상태 → ② 질문 제목·내용 → ③ 답변 내용(있는 경우) → ④ 가능한 조작
  (수정/삭제 또는 답변 작성/수정)

## 6. 화면별 필수 콘텐츠

**메인 페이지**
- 서비스명(QANOW) 워드마크
- 한 줄 소개 카피
- "질문 작성 → 관리자 확인 → 답변 확인" 3단계 이용 흐름 시각화
- 질문 작성 CTA
- 로그인 상태에 따른 로그인/로그아웃 진입점

**질문 리스트 페이지**
- 역할에 맞는 목록(회원: 본인 질문만 / 관리자: 전체 질문)
- 상태 필터(전체 / 답변 대기 / 답변 완료)
- 목록 항목: 제목, 상태 배지(텍스트 포함), 등록일시, (관리자 뷰) 작성자 닉네임
- 회원 전용 질문 작성 CTA
- 빈 목록 상태(역할별로 6번·10번 항목 참조)

**질문 페이지**
- 제목/내용 입력 또는 표시 영역
- 답변 상태 배지
- 답변 내용 영역(답변 완료 시) 또는 답변 대기 안내(대기 시)
- 회원 전용(답변 전): 수정/삭제 조작
- 관리자 전용: 답변 작성/수정 폼
- 글자수 카운터(제목 100자, 내용/답변 5000자)

## 7. 화면별 주요 CTA

| 화면 | 역할 | 주요 CTA |
|---|---|---|
| 메인 | 전체 | 질문 작성하기(1차), 로그인/회원가입(보조) |
| 질문 리스트 | 회원 | 질문 작성하기 |
| 질문 리스트 | 관리자 | 없음 (목록 항목 클릭이 곧 진입 동작) |
| 질문 페이지 (답변 전) | 회원 | 수정, 삭제 |
| 질문 페이지 (답변 후) | 회원 | 없음 (읽기 전용 안내만) |
| 질문 페이지 (답변 대기) | 관리자 | 답변 등록 |
| 질문 페이지 (답변 완료) | 관리자 | 답변 수정 |

## 8. 회원과 관리자 상태 차이

| 구분 | 회원 | 관리자 |
|---|---|---|
| 리스트 범위 | 본인 질문만 | 전체 질문 |
| 리스트의 작성자 표시 | 불필요(본인이므로) | 닉네임 표시 |
| 질문 페이지 조작 | 답변 전 수정/삭제 가능, 답변 후 읽기 전용 | 답변 작성/수정 |
| 빈 목록 CTA | 있음("질문 작성하기") | 없음(안내 문구만) |
| 접근 제한 | 타인의 질문 조회·수정·삭제 불가 | 답변 작성 권한 없음(회원 기준) |

## 9. 페이지 간 이동 구조

- 메인 → CTA 클릭 → 비로그인 시 로그인 화면(성공 후 원래 목적지로 복귀) / 로그인 시 질문 페이지
  (신규 작성 모드)
- 비회원이 보호된 화면(질문 리스트/질문 페이지)에 직접 접근 → 로그인 화면 → 성공 시 원래 화면
  복귀
- 질문 리스트 → 항목 클릭 → 질문 페이지(상세/수정 모드)
- 질문 리스트(회원) → CTA → 질문 페이지(신규 작성 모드)
- 질문 페이지(신규 작성, 저장 성공) → 동일 화면이 상세 모드로 전환
- 상단 내비게이션에는 항상 "메인"과 (로그인 시) "질문 목록" 진입점을 유지해 어느 화면에서도
  동일한 복귀 경로를 제공한다.

## 10. 콘텐츠 예시 문구

- 메인 한 줄 소개: "궁금한 걸 물어보세요. 관리자가 직접 답합니다."
- 이용 흐름 라벨: "질문 작성" · "관리자 확인" · "답변 확인"
- 공통 CTA: "질문 작성하기"
- 상태 배지: "답변 대기" / "답변 완료"
- 회원 빈 목록: "아직 등록한 질문이 없어요. 첫 질문을 남겨보세요." + [질문 작성하기]
- 관리자 빈 목록(필터 적용 시): "해당 상태의 질문이 없습니다."
- 답변 완료 후 변경 불가 안내: "답변이 완료된 질문은 더 이상 수정하거나 삭제할 수 없어요."
- 로그인 필요 안내: "로그인이 필요한 화면이에요. 로그인 후 이어서 진행할 수 있어요."
- 오류 상태: "문제가 발생했어요. 다시 시도해주세요." + [다시 시도]
- 저장 중: "저장 중입니다..."

## 11. 색상 역할

- **메인 페이지(Hero)**: 어두운 네이비 배경 위 블루·바이올렛 그라데이션(오로라)을 포인트로
  사용. 텍스트는 밝은 오프화이트로 충분한 대비를 확보한다.
- **내부 페이지(질문 리스트/질문 페이지)**: 밝고 정돈된 라이트 서페이스(오프화이트~라이트
  그레이) 배경에 다크 네이비 계열 텍스트로 가독성을 우선한다.
- 포인트 컬러(블루/바이올렛)는 CTA 버튼, 활성 배지, 링크, 포커스 링 등 제한된 요소에만
  사용하고, 본문이나 큰 배경 면에는 사용하지 않는다.
- 상태 배지는 색상만으로 구분하지 않고 반드시 텍스트를 동반한다. 예: "답변 대기"는 중립/앰버
  계열 + 텍스트, "답변 완료"는 포인트 블루 계열 + 텍스트.
- 오류/경고는 별도의 경고색(레드 계열)을 텍스트와 함께 사용한다.

## 12. 타이포그래피 방향

- 메인 페이지 헤드라인은 크고 굵은 웨이트(700~800 수준)로 강한 첫인상을 주되, 신뢰감을 해치는
  과도한 장식체는 피한다.
- 내부 화면(리스트/질문 페이지)은 가독성 우선의 중간 굵기(400~500) 본문 서체와, 제목 > 상태
  배지/라벨 > 본문 > 보조 텍스트 순의 명확한 크기 위계를 사용한다.
- 한글 가독성을 위해 본문 줄간격은 1.5~1.7배 수준으로 넉넉히 확보한다.
- 글자수 카운터, 등록일시 등 숫자는 흔들림 없이 보이도록 고정폭/표 형식 숫자 처리를 고려한다.

## 13. 간격과 레이아웃 방향

- 내부 화면은 좌우 여백이 일정한 단일 컬럼 중심 레이아웃을 사용하며, 질문 페이지는 읽기 흐름을
  방해하지 않도록 본문 폭을 제한한다.
- 리스트 항목은 상태 배지·제목·메타정보가 한 줄에서 명확히 구분되도록 충분한 내부 간격을
  두되, 한 화면에 너무 적은 항목만 보이지 않게 밀도와 여백의 균형을 맞춘다.
- 메인 페이지는 Hero → 이용 흐름 → CTA 순으로 섹션 간 여백을 명확히 구분해 스크롤 리듬을
  만든다.
- 촘촘한 다단 그리드보다 명확한 좌우 여백과 콘텐츠 폭 제한을 우선한다.

## 14. 버튼·입력창·카드·배지 규칙

- **버튼**: 화면당 1차 CTA(질문 작성하기, 답변 등록 등)는 포인트 컬러 solid 버튼 하나만 명확히
  두고, 나머지는 outline/텍스트 버튼으로 위계를 낮춘다. 절제된 radius를 사용하며 완전한 pill
  형태는 지양한다.
- **입력창**: 제목/내용/답변 입력창은 포커스 시 명확한 아웃라인을 제공하고, 글자수 제한에 근접·
  초과 시 카운터가 색상과 텍스트로 함께 경고한다.
- **카드**: 질문 리스트 항목과 메인 페이지의 질문·답변 플로팅 카드는 절제된 radius와 얇은
  보더/그림자를 사용하고, 과도하게 둥근 모서리나 다중 그림자 레이어는 피한다.
- **배지**: 답변 상태 배지는 (아이콘 선택) + 텍스트 조합을 기본으로 하며, 색상은 보조 신호로만
  사용한다.

## 15. 메인 페이지 시각 효과 규칙

- 오로라 그라데이션은 Hero 배경에만 적용하고, 본문 텍스트 위나 내부 페이지에는 사용하지 않는다.
- 미세한 그리드 패턴은 저대비 배경 텍스처 수준에 그치며 텍스트 가독성을 해치지 않는다.
- 질문·답변 플로팅 카드는 장식 요소로 예시 문구만 담고, 반복적인 큰 움직임보다 은은한 정지/서행
  움직임으로 제한한다.
- 시각 효과는 Hero 영역에만 적용하고, 이용 흐름 설명 섹션부터는 정돈된 라이트 배경으로 전환해
  내부 화면과의 톤을 자연스럽게 연결한다.
- 모든 배경 효과는 텍스트 대비 기준을 통과해야 하며 반복 렌더링으로 인한 성능 저하를 유발하지
  않아야 한다.

## 16. 로딩·빈 화면·오류·권한 없음 상태

질문 리스트와 질문 페이지 등 모든 데이터 화면에 다음 5개 상태를 일관된 패턴으로 적용한다.

- **로딩**: 콘텐츠 영역에 중립적 로딩 표시 + "불러오는 중..." 텍스트.
- **빈 목록**: 회원은 안내 문구 + "질문 작성하기" CTA, 관리자는 안내 문구만(CTA 없음).
- **오류**: 오류 안내 문구 + "다시 시도" 버튼, 색상과 함께 반드시 텍스트로 오류임을 명시.
- **권한 없음**: 데이터를 노출하지 않고 안내 텍스트만 표시하거나 로그인 화면으로 이동시킨다.
- **저장 중**: 저장 버튼을 비활성화하고 "저장 중..." 텍스트로 중복 제출을 방지한다.

## 17. 모바일 반응형 기준

- 질문 등록, 질문 조회, 답변 확인, 관리자 답변 작성이라는 핵심 시나리오는 모바일에서도 중단
  없이 완료되어야 한다.
- **모바일 내비게이션**: 하단 탭바 대신 상단 앱바(로고 + 햄버거 메뉴) 구조로 단순화한다. 화면
  수가 적은 MVP 특성상 하단 탭바는 과설계이며 단순한 MVP 우선 원칙에 맞지 않는다. 햄버거 메뉴에는
  "메인", (로그인 시) "질문 목록", 로그인/로그아웃만 포함한다.
- 질문 리스트(회원)의 "질문 작성하기" CTA는 모바일에서 화면 하단 고정(sticky) 버튼으로 노출해
  스크롤 중에도 한 손으로 접근 가능하게 한다.
- 질문 페이지의 입력 영역(제목/내용/답변)은 모바일에서 세로 스택 레이아웃으로 전환하고, 저장/
  취소 등 조작 버튼은 화면 하단에 고정한다.
- 데스크톱에서 다단 배치되던 메타정보(상태, 작성자, 등록일시)는 모바일에서 세로로 재배열하되
  5번 항목의 정보 우선순위를 그대로 유지한다.

## 18. 접근성과 모션 감소 기준

- 오로라 그라데이션, 플로팅 카드, 전환 효과 등 모든 애니메이션은 `prefers-reduced-motion`
  사용자에게 정적인 상태로 대체되어야 한다.
- 질문 작성, 답변 작성, 로그인 등 주요 행동은 키보드만으로 완결 가능해야 하며, 포커스 순서와
  포커스 표시가 명확해야 한다.
- 상태 정보(답변 대기/완료, 오류, 권한 없음)는 색상만으로 구분하지 않고 반드시 텍스트를 함께
  제공한다.
- 텍스트와 배경의 명도 대비는 WCAG AA 수준을 만족해야 하며, 특히 Hero의 어두운 배경 위 텍스트
  대비를 반드시 확인한다.

## 19. 만들지 말아야 할 디자인

- 과도한 Glassmorphism(반투명 블러 카드 남용)
- 모든 카드/버튼에 일괄적으로 과도하게 둥근(pill 수준) 모서리를 적용하는 것
- 전형적인 "AI 스타트업 랜딩 페이지" 톤(근거 없는 통계 배너, 빽빽한 로고 클라우드, 과도한 3D
  아이콘 등)
- spec.md에 없는 기능을 암시하는 UI(검색창, 페이지네이션 컨트롤, 댓글 입력창, 소셜 로그인
  버튼, 통계 대시보드 위젯, 파일 첨부 버튼 등)
- 상태를 색상 점(dot)만으로 표시하고 텍스트를 생략한 배지
- 메인 페이지의 시각 효과가 내부 질문 리스트/질문 페이지까지 과도하게 이어져 가독성을 해치는 것

## 20. Claude Design 시안 평가 기준

1. 메인 페이지가 QANOW의 목적과 이용 흐름을 별도 설명 없이 전달하는가?
2. 메인 Hero의 시각 효과가 텍스트 가독성과 성능을 해치지 않는가?
3. 세 핵심 화면이 동일한 정보 구조와 디자인 언어를 공유하는가?
4. 답변 상태가 색상과 텍스트를 함께 사용해 구분되는가?
5. 회원/관리자 뷰의 차이(리스트 범위, CTA 유무, 조작 권한)가 시안에 정확히 반영되었는가?
6. 로딩/빈 목록/오류/권한 없음/저장 중 5개 상태가 모두 시안에 존재하는가?
7. 모바일 시안에서 질문 작성과 답변 확인이 데스크톱과 동일하게 완결 가능한가?
8. 애니메이션에 `prefers-reduced-motion` 대응이 명시되어 있는가?
9. spec.md에 없는 기능(검색, 페이지네이션, 댓글, 소셜 로그인, 통계 대시보드, 파일 첨부)이
   시안에 등장하지 않는가?
10. "만들지 말아야 할 디자인"(19번 항목)에 해당하는 요소가 시안에 없는가?
