# Feature Specification: QANOW 질문-답변 게시판

**Feature Branch**: `001-qa-board`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: "QANOW라는 회원 질문·관리자 답변 게시판을 만들고 싶다. 회원은 질문을 남기고 자신의
질문·답변 상태를 확인하며, 관리자는 답변이 필요한 질문을 찾아 답변한다. 메인 페이지, 질문 리스트 페이지,
질문 페이지의 3개 핵심 화면으로 구성되며, 비회원/회원/관리자 3개 역할과 각 역할별 권한 규칙, 입력
길이 규칙, 로딩/빈 목록/오류/권한 없음/저장 중 상태를 포함한다. 파일 첨부, 댓글, 검색, 페이지네이션,
소셜 로그인, 통계 대시보드는 MVP 범위에서 제외한다."

## Clarifications

### Session 2026-09-25

- Q: 질문 작성·상세·수정 화면을 하나의 일관된 정보 구조 패턴으로 만들 것인가요, 아니면 목적별로
  다른 레이아웃을 쓸 것인가요? → A: 하나의 통합 레이아웃(제목·내용·답변 영역)을 작성/상세/수정
  모드가 공유하고, 모드에 따라 입력 가능 여부만 달라진다.
- Q: 회원가입 시 이메일·비밀번호 외에 별도의 표시용 이름(닉네임) 필드가 필요한가요? → B: 이메일,
  비밀번호에 닉네임(표시용 이름)을 추가로 받고, 관리자 목록에는 닉네임을 작성자로 표시한다.
- Q: 질문 리스트 화면에 "답변 대기 / 답변 완료" 상태 필터가 필요한가요? → B: 상태 필터(전체/답변
  대기/답변 완료) 탭 또는 드롭다운을 제공한다.
- Q: 비회원이 보호된 화면에 접근하면 어떤 방식으로 로그인 안내를 보여줄 것인가요? → A: 로그인
  페이지로 이동시키고, 로그인 성공 후 원래 접근하려던 화면으로 돌아간다.
- Q: 빈 목록 화면에서 회원과 관리자에게 각각 어떤 행동을 안내할 것인가요? → A: 회원의 빈
  목록에는 "질문 작성하기" CTA를 보여주고, 관리자의 빈 목록에는 안내 문구만 표시한다(CTA 없음).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원의 질문 등록 및 상태 확인 (Priority: P1)

로그인한 회원은 궁금한 점을 질문으로 등록하고, 자신이 등록한 질문 목록과 각 질문의 상세 내용,
그리고 관리자 답변 여부(답변 대기/답변 완료)를 언제든지 확인할 수 있다.

**Why this priority**: "질문을 남기고 상태를 확인한다"는 QANOW의 가장 근본적인 가치이며, 이
흐름 없이는 관리자 답변도, 메인 페이지 안내도 의미가 없다. 이 스토리 하나만 구현해도 회원이
질문을 남기고 스스로 진행 상황을 추적할 수 있는 최소 기능 제품이 된다.

**Independent Test**: 회원으로 가입·로그인한 뒤 질문을 작성하고, 질문 목록 화면에서 해당
질문이 "답변 대기" 상태로 보이는지, 질문 상세 화면에서 작성한 내용이 그대로 보이는지 확인하는
것만으로 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원이 질문 작성 화면에 있을 때, **When** 제목과 내용을 규칙에 맞게
   입력하고 등록하면, **Then** 질문이 저장되고 질문 상세 화면으로 이동하며 상태는 "답변 대기"로
   표시된다.
2. **Given** 질문을 1건 이상 등록한 회원이 질문 리스트 페이지에 접근했을 때, **When** 목록을
   조회하면, **Then** 자신이 작성한 질문만 최신순으로 보이고 각 질문 옆에 답변 상태(답변
   대기/답변 완료)가 텍스트로 표시된다.
3. **Given** 관리자가 아직 답변하지 않은 자신의 질문을 회원이 열람할 때, **When** 질문 상세
   화면을 열면, **Then** 질문 내용과 "답변 대기" 상태만 보이고 답변 영역은 비어 있음이 표시된다.
4. **Given** 관리자가 답변을 완료한 자신의 질문을 회원이 열람할 때, **When** 질문 상세 화면을
   열면, **Then** 질문 내용과 함께 관리자 답변 내용, "답변 완료" 상태가 표시된다.

---

### User Story 2 - 관리자의 답변 처리 (Priority: P2)

관리자는 전체 회원의 질문 목록에서 답변이 필요한(대기 중인) 질문을 찾아 상세 내용을 확인하고
답변을 작성하거나, 이미 작성한 답변을 수정할 수 있다.

**Why this priority**: 회원이 질문을 등록해도(User Story 1) 관리자가 답변하지 않으면 서비스의
핵심 약속(질문에 답을 받는다)이 완성되지 않는다. 다만 질문 등록·조회 없이는 답변할 대상이 없으므로
P1 다음 순위다.

**Independent Test**: 관리자로 로그인해 전체 질문 목록에서 답변 대기 필터로 대상을 추려내고,
질문 하나를 선택해 답변을 작성/저장한 뒤 상태가 "답변 완료"로 바뀌는 것을 확인하는 것만으로
독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 관리자가 질문 리스트 페이지에 접근했을 때, **When** 목록을 조회하면, **Then** 모든
   회원의 질문이 보이고 각 질문의 답변 상태(답변 대기/답변 완료)가 텍스트로 구분되어 표시된다.
2. **Given** 답변 대기 상태인 질문의 상세 화면에 관리자가 있을 때, **When** 답변 내용을 규칙에
   맞게 입력하고 저장하면, **Then** 답변이 저장되고 질문 상태가 "답변 완료"로 바뀌며 해당 회원이
   조회 시 답변 내용을 볼 수 있다.
3. **Given** 이미 답변이 등록된 질문의 상세 화면에 관리자가 있을 때, **When** 답변 내용을 수정하고
   저장하면, **Then** 수정된 답변 내용이 저장되고 회원에게도 갱신된 내용이 보인다.

---

### User Story 3 - 답변 전 질문 수정·삭제 (Priority: P3)

회원은 관리자가 아직 답변하지 않은 자신의 질문에 한해 내용을 수정하거나 삭제할 수 있다.

**Why this priority**: 오탈자 수정이나 잘못 등록한 질문 정리는 사용성을 높이지만, 질문 등록·조회
(P1)와 관리자 답변(P2)이 먼저 동작해야 "답변 전"이라는 조건 자체를 검증할 수 있으므로 그 다음
순위다.

**Independent Test**: 답변 대기 중인 자신의 질문 상세 화면에서 수정 또는 삭제를 수행해 반영되는지,
그리고 답변이 완료된 질문에서는 수정·삭제 버튼이 동작하지 않는지 확인하는 것만으로 독립적으로
검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 답변 대기 중인 자신의 질문 상세 화면에 회원이 있을 때, **When** 제목이나 내용을
   규칙에 맞게 수정하고 저장하면, **Then** 변경 내용이 저장되고 상세 화면에 즉시 반영된다.
2. **Given** 답변 대기 중인 자신의 질문 상세 화면에 회원이 있을 때, **When** 삭제를 요청하고
   확인하면, **Then** 질문이 삭제되고 목록에서 더 이상 보이지 않는다.
3. **Given** 관리자가 이미 답변을 완료한 자신의 질문 상세 화면에 회원이 있을 때, **When** 수정
   또는 삭제를 시도하면, **Then** 시스템은 이를 거부하고 답변 완료 후에는 수정·삭제할 수 없다는
   안내를 보여준다.

---

### User Story 4 - 메인 페이지를 통한 서비스 이해 (Priority: P4)

방문자(비회원 포함)는 메인 페이지에서 QANOW가 무엇을 하는 서비스인지, 그리고 "질문 작성 → 관리자
확인 → 답변 확인"으로 이어지는 이용 흐름을 별도 안내 없이 이해할 수 있으며, 질문 작성으로 바로
이동할 수 있다.

**Why this priority**: 메인 페이지는 신규 방문자의 이해를 돕는 진입점이지만, 실제 핵심 가치는
질문 등록·조회(P1)와 답변(P2)에서 발생한다. 메인 페이지가 없어도 나머지 기능은 동작하므로 가장
낮은 우선순위로 둔다.

**Independent Test**: 로그인하지 않은 상태로 메인 페이지에 접속해 서비스 소개, 이용 흐름 설명,
질문 작성 CTA가 모두 노출되는지, CTA 클릭 시 다음 단계(로그인 안내 또는 질문 작성)로 정상
이동하는지 확인하는 것만으로 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 비회원이 메인 페이지에 접속했을 때, **When** 페이지를 살펴보면, **Then** 서비스
   소개 문구와 "질문 작성 → 관리자 확인 → 답변 확인"으로 이어지는 이용 흐름 설명이 함께 보인다.
2. **Given** 비회원이 메인 페이지의 질문 작성 CTA를 클릭했을 때, **When** 이동이 이루어지면,
   **Then** 로그인 화면으로 이동하고, 로그인에 성공하면 질문 작성 화면으로 돌아간다.
3. **Given** 로그인한 회원이 메인 페이지의 질문 작성 CTA를 클릭했을 때, **When** 이동이 이루어지면,
   **Then** 질문 작성 화면으로 바로 이동한다.

---

### Edge Cases

- 비회원이 질문 리스트 페이지나 질문 상세/작성 화면 등 보호된 화면에 직접 URL로 접근하면 어떻게
  되는가? → 로그인 화면으로 이동되며, 로그인에 성공하면 원래 접근하려던 화면으로 돌아간다.
- 회원이 다른 회원의 질문 상세 URL을 직접 열거나 수정·삭제를 시도하면 어떻게 되는가? → 시스템은
  조회·수정·삭제를 모두 거부하고 권한 없음 상태를 보여준다.
- 일반 회원이 답변 작성 요청을 시도하면(예: API 직접 호출) 어떻게 되는가? → 시스템은 요청을
  거부하고 권한 없음으로 처리한다.
- 관리자가 이미 답변을 완료한 질문에 회원이 수정·삭제를 시도하면 어떻게 되는가? → 시스템은 요청을
  거부하고 답변 완료 후에는 변경할 수 없다는 안내를 보여준다.
- 질문 제목/내용/답변에 공백만 입력하거나 글자 수 제한(제목 100자, 내용/답변 5000자)을 초과하면
  어떻게 되는가? → 저장이 거부되고 구체적인 입력 오류가 표시된다.
- 회원이 아직 질문을 하나도 등록하지 않았다면 질문 리스트 페이지는 어떻게 보이는가? → 빈 목록
  상태와 함께 "질문 작성하기" CTA가 표시되어 질문 작성으로 바로 이동할 수 있다.
- 관리자가 조회 중인 필터(전체/답변 대기/답변 완료)에 해당하는 질문이 하나도 없다면 어떻게
  보이는가? → 빈 목록 상태와 안내 문구만 표시되며, 관리자에게는 질문 작성 CTA를 제공하지 않는다.
- 목록이나 상세 데이터를 불러오는 도중 네트워크·서버 오류가 발생하면 어떻게 되는가? → 로딩
  상태에서 오류 상태로 전환되고 재시도 방법이 안내된다.
- 저장(질문 등록/수정, 답변 등록/수정) 처리 중 사용자가 같은 요청을 중복 제출하면 어떻게 되는가?
  → 저장 중 상태로 전환되어 중복 제출이 방지되고, 완료 또는 오류 상태로만 전이된다.
- 삭제되었거나 존재하지 않는 질문의 상세 URL에 접근하면 어떻게 되는가? → 오류 상태(찾을 수 없음)
  가 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 비회원이 이메일, 비밀번호, 닉네임(표시용 이름)을 입력해 회원가입할 수
  있도록 해야 한다.
- **FR-002**: 시스템은 회원이 로그인하고 로그아웃할 수 있도록 해야 한다.
- **FR-003**: 시스템은 관리자가 별도의 관리자 계정으로 로그인할 수 있도록 해야 한다.
- **FR-004**: 시스템은 로그인한 회원이 질문 제목과 내용을 입력해 질문을 등록할 수 있도록 해야
  한다.
- **FR-005**: 시스템은 질문 제목을 공백 제거 후 1자 이상 100자 이하로, 질문 내용을 공백 제거 후
  1자 이상 5000자 이하로 검증해야 하며, 조건을 만족하지 않으면 저장을 거부하고 오류를 안내해야
  한다.
- **FR-006**: 시스템은 로그인한 회원이 자신이 작성한 질문 목록만 조회할 수 있도록 해야 한다.
- **FR-007**: 시스템은 관리자가 전체 회원의 질문 목록을 조회할 수 있도록 해야 하며, 각 질문의
  작성자 닉네임과 답변 상태(답변 대기/답변 완료)를 구분해 보여줘야 한다.
- **FR-008**: 시스템은 회원과 관리자 모두 질문 상세 화면에서 질문 내용과 답변 상태, 그리고 답변이
  있는 경우 답변 내용을 확인할 수 있도록 해야 한다.
- **FR-009**: 시스템은 관리자가 답변 대기 중인 질문에 답변 내용을 입력해 등록할 수 있도록 해야
  한다.
- **FR-010**: 시스템은 답변 내용을 공백 제거 후 1자 이상 5000자 이하로 검증해야 하며, 조건을
  만족하지 않으면 저장을 거부하고 오류를 안내해야 한다.
- **FR-011**: 시스템은 관리자가 이미 등록한 답변 내용을 수정할 수 있도록 해야 한다.
- **FR-012**: 시스템은 답변이 등록되면 해당 질문의 상태를 "답변 대기"에서 "답변 완료"로 자동
  전환해야 한다.
- **FR-013**: 시스템은 답변이 등록되기 전인 자신의 질문에 한해 회원이 제목과 내용을 수정할 수
  있도록 해야 한다.
- **FR-014**: 시스템은 답변이 등록되기 전인 자신의 질문에 한해 회원이 질문을 삭제할 수 있도록
  해야 한다.
- **FR-015**: 시스템은 관리자가 답변을 등록한 이후에는 해당 질문에 대한 회원의 수정·삭제 요청을
  거부하고, 그 사유(답변 완료 후 변경 불가)를 안내해야 한다.
- **FR-016**: 시스템은 회원이 다른 회원의 질문을 조회, 수정, 삭제하려는 모든 시도를 거부해야
  한다.
- **FR-017**: 시스템은 일반 회원의 답변 작성·수정 요청을 모두 거부해야 한다.
- **FR-018**: 시스템은 비회원이 질문 작성, 질문 리스트, 질문 상세 등 보호된 화면에 접근하면 실제
  데이터를 노출하지 않고 로그인 화면으로 이동시켜야 하며, 로그인에 성공하면 원래 접근하려던
  화면으로 되돌려야 한다.
- **FR-019**: 시스템은 메인 페이지에서 서비스 소개, 질문 작성 CTA, "질문 작성 → 관리자 확인 →
  답변 확인"으로 이어지는 이용 흐름 설명을 제공해야 한다.
- **FR-020**: 시스템은 데이터를 불러오는 동안 로딩 상태를, 목록에 항목이 없을 때 빈 목록 상태를,
  요청 처리 중 오류가 발생하면 오류 상태를, 권한이 없는 접근에는 권한 없음 상태를, 저장 요청 처리
  중에는 저장 중 상태를 각각 텍스트로 구분해 보여줘야 한다.
- **FR-021**: 시스템은 질문 작성, 질문 상세 확인, 질문 수정을 하나의 통합된 화면 레이아웃(제목·
  내용·답변 영역)으로 제공해야 하며, 신규 작성/조회/수정 모드에 따라 각 영역의 입력 가능 여부만
  달라져야 한다.
- **FR-022**: 시스템은 질문 리스트 화면(회원/관리자 공통)에서 전체/답변 대기/답변 완료 상태로
  목록을 필터링할 수 있는 기능을 제공해야 한다.

### Key Entities

- **계정 (Account)**: 이메일, 비밀번호(자격 증명), 닉네임(표시용 이름), 역할(회원 또는 관리자)을
  가지며, 질문 또는 답변의 작성자를 식별하는 데 사용된다. 닉네임은 관리자의 전체 질문 목록에서
  작성자 표시에 쓰인다.
- **질문 (Question)**: 제목, 내용, 작성자(회원), 상태(답변 대기/답변 완료), 등록 일시, 최종 수정
  일시를 가진다. 정확히 한 계정에 속하며, 최대 한 건의 답변과 연결된다.
- **답변 (Answer)**: 내용, 작성자(관리자), 등록 일시, 최종 수정 일시를 가진다. 정확히 하나의
  질문에 연결되며, 질문 하나에는 답변이 없거나 하나만 존재한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 신규 방문자는 별도 설명 없이 메인 페이지만 보고 "질문을 남기면 관리자가 답변한다"는
  이용 흐름을 이해하고 질문 작성으로 이동할 수 있다.
- **SC-002**: 회원은 회원가입부터 첫 질문 등록 완료까지 3분 이내에 마칠 수 있다.
- **SC-003**: 회원은 자신의 질문 목록에서 각 질문의 답변 상태(답변 대기/답변 완료)를 한눈에,
  색상에 의존하지 않고도 텍스트만으로 구분할 수 있다.
- **SC-004**: 관리자는 답변 대기 질문을 찾아 답변을 작성·저장하는 과정을 별도 검색 기능 없이
  목록 조회와 상태 필터만으로 완료할 수 있다.
- **SC-005**: 질문 등록, 질문 조회, 답변 확인, 관리자 답변 작성이라는 핵심 시나리오는 데스크톱과
  모바일 환경 모두에서 중단 없이 끝까지 완료된다.
- **SC-006**: 권한이 없는 조회·수정·삭제 시도(다른 회원의 질문, 답변 완료된 질문 변경, 비회원의
  보호된 화면 접근, 일반 회원의 답변 작성)는 100% 차단되며 실제 데이터가 노출되지 않는다.
- **SC-007**: 유효하지 않은 입력(공백만 입력, 길이 초과)으로 인한 저장 시도는 100% 거부되고
  사용자는 무엇이 잘못되었는지 구체적으로 안내받는다.

## Assumptions

- 관리자 계정은 서비스 운영자가 사전에 생성하며, 회원가입 화면을 통한 자체 관리자 가입 절차는
  MVP 범위에 포함하지 않는다.
- 질문 하나에는 답변이 최대 한 건만 존재하며(스레드형 다중 답변 없음), 관리자는 필요 시 기존
  답변을 덮어쓰듯 수정한다.
- 답변 등록·수정에 대한 이메일/푸시 등 알림 기능은 MVP 범위에 포함하지 않으며, 회원은 직접 질문
  상세 화면을 다시 확인해 답변 여부를 확인한다.
- 질문 삭제는 목록과 상세 화면에서 더 이상 조회되지 않는 것을 의미하며, 데이터 보존 방식(완전
  삭제 여부)은 이 명세의 범위를 벗어난 구현 세부사항으로 둔다.
- 회원가입 시 이메일 인증(이중 확인) 절차는 MVP 범위에 포함하지 않으며, 가입 즉시 로그인 및
  질문 등록이 가능하다고 가정한다.
- 파일 첨부, 댓글, 검색, 페이지네이션, 소셜 로그인, 통계 대시보드는 사용자가 명시적으로 MVP에서
  제외했으므로 이번 명세의 요구사항에 포함하지 않는다.
